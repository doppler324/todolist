# TodoDock — дизайн-документ (v0.1)

Приложение для Windows 11: постоянно видимая «ручка» у правого края экрана,
из которой выезжает панель задач с папками и постоянными уведомлениями,
с дублированием уведомлений в Telegram.

## 1. Цели и не-цели

**Цели**
- Всегда на экране, но не мешает работе (узкая ручка у правого края).
- Быстрое добавление задач, группировка по папкам.
- Уведомления, которые висят, пока пользователь сам их не закроет.
- Отправка уведомлений в Telegram.
- Нативный вид Windows 11 (Mica/Acrylic, скруглённые углы, тёмная/светлая тема).

**Не-цели (v1)**: синхронизация между устройствами, мобильное приложение, совместная работа.

## 2. Технологический стек (рекомендация)

| Решение | Выбор | Почему |
|---|---|---|
| Платформа | **.NET 8 + WPF** | Полный контроль над окнами (topmost, анимации, no-activate), малый расход памяти, нативные API |
| Стили | WPF-UI (Fluent) или собственные ресурсы | Mica/Acrylic, Fluent-вид Win11 |
| Хранилище | **SQLite** (`%LOCALAPPDATA%\TodoDock\data.db`) через EF Core / Dapper | Надёжно, просто, бэкап = копия файла |
| Telegram | Bot API по HTTPS (`HttpClient`) | Без сторонних зависимостей |
| Секреты | DPAPI (`ProtectedData`) | Токен бота не лежит открытым текстом |
| Трей / автозапуск | `NotifyIcon` + ключ `HKCU\...\Run` | Запуск при входе в систему |
| Установка | MSIX или Inno Setup | Автозапуск, обновления |

Альтернативы (Tauri, Electron) отвергнуты: тяжелее и хуже для always-on-top/неактивируемых окон.

## 3. Основной UX

### 3.1 Ручка (Handle)
- Узкое окно ~6–10 px шириной, ~96 px высотой у правого края, по вертикали по центру
  (позицию можно перетащить вверх/вниз; запоминается).
- Borderless, `Topmost`, `WS_EX_TOOLWINDOW` (нет в Alt+Tab), `WS_EX_NOACTIVATE`
  (не крадёт фокус).
- Стилизация: скруглённая «таблетка» с акцентным цветом системы, лёгкое свечение при наведении,
  при наведении расширяется до ~24 px и показывает шеврон `‹`.
- Бейдж с числом активных уведомлений/просроченных задач (красная точка).
- Клик (или hover > 300 мс, настраивается) → панель выезжает.

### 3.2 Выезжающая панель (Drawer)
- Ширина 380 px, высота = рабочая область экрана (без панели задач).
- Анимация: слайд справа налево 200 мс, ease-out; закрытие — клик по ручке, `Esc`,
  клик вне панели (опционально «закрепить» булавкой).
- Фон Mica/Acrylic, скругление 12 px, тень.
- Учитывает DPI, несколько мониторов (ручка на выбранном мониторе, по умолчанию — основной).

```
┌──────────────────────────────┐
│ TodoDock            📌  ⚙   │  заголовок
├──────────────────────────────┤
│ [ + Новая задача…        ⏎ ] │  быстрый ввод
├──────────────────────────────┤
│ ▾ 📁 Работа              (4) │
│    ☐ Отчёт за квартал  🔔 18:00│
```

### 3.3 Задачи
- Поля: название, заметка, папка, дедлайн, напоминание (разовое/повтор), приоритет, статус.
- Быстрый ввод: Enter добавляет в выбранную папку; синтаксис `#папка`, `!высокий`, `@завтра 18:00`.
- Чекбокс завершает задачу (анимация, «отменить» 5 сек).
- Drag & drop: порядок задач и перенос между папками.
- Редактирование inline (двойной клик / раскрытие карточки).

### 3.4 Папки
- Плоская иерархия в v1 (1 уровень), цвет и иконка (emoji) на папку.
- Создание/переименование/удаление (при удалении — спросить: перенести задачи или удалить).
- Сворачивание/разворачивание, счётчик активных задач, drag & drop сортировка.
- Фильтры-«умные папки»: Сегодня, Просрочено, Выполнено.

## 4. Уведомления (ключевое требование)

**Принцип: уведомление не исчезает само. Только явное закрытие пользователем.**

- Не используем стандартные Windows toast (они автоскрываются и уходят в Центр уведомлений).
  Вместо этого — собственные окна-карточки:
  - `Topmost`, без фокуса, стек в правом нижнем углу над панелью задач (или у ручки),
    новые сверху, анимация появления.
  - Содержимое: заголовок, текст, время, имя папки, кнопки.
  - Кнопки: **Закрыть** (✕), **Отложить** (5 мин / 15 мин / 1 час / до завтра), **Выполнено**.
  - Без таймера автоскрытия. Закрыть можно только кнопкой.
- Устойчивость: незакрытые уведомления сохраняются в БД (`status = active`) и
  **восстанавливаются после перезапуска приложения/перезагрузки ПК**.
- Много уведомлений: показываем до N (5) карточек, остальные сворачиваются в «+3 ещё»;
  полный список — на вкладке «Уведомления» в панели.
- Звук (опционально, на уведомление), мигание ручки пульсацией до закрытия.
- Режим «Не беспокоить» (опц.): уведомления накапливаются без звука, но не теряются.
- Источники уведомлений: срабатывание напоминания/дедлайна задачи, просрочка,
  ручное «напомнить через…». Повторяющиеся — создают новую карточку по расписанию.

### Планировщик
- Фоновый сервис: таймер на ближайшее срабатывание из БД (не опрос раз в секунду).
- Пересчёт при системном пробуждении (`SystemEvents.PowerModeChanged`) и смене времени;
  пропущенные за время сна срабатывают сразу после пробуждения.

## 5. Интеграция с Telegram

- Пользователь создаёт бота через @BotFather и вставляет **токен** в настройках.
- Привязка чата: кнопка «Привязать» → пользователь пишет боту `/start` →
  приложение читает `getUpdates`, сохраняет `chat_id`. Кнопка «Тестовое сообщение».
- Отправка: `POST https://api.telegram.org/bot<token>/sendMessage` (`parse_mode=HTML`).
- Настройки: глобальный переключатель + флажок «слать в Telegram» на уровне задачи/папки/напоминания.
- Надёжность: очередь исходящих (`telegram_outbox` в БД), ретраи с экспоненциальной задержкой,
  работает при временном отсутствии сети.
- (Опционально, v2) inline-кнопки в Telegram «Выполнено / Отложить» с обратной связью
  через long polling `getUpdates`.
- Безопасность: токен шифруется DPAPI; принимаем сообщения только от привязанного `chat_id`.

## 6. Модель данных (SQLite)

```
folders(id, name, color, icon, sort_order, created_at)
tasks(id, folder_id NULL, title, note, priority, status[open|done],
      due_at NULL, repeat_rule NULL, sort_order, created_at, completed_at NULL)
reminders(id, task_id, fire_at, repeat_rule NULL, send_telegram, status[pending|fired|cancelled])
notifications(id, task_id NULL, reminder_id NULL, title, body, created_at,
              status[active|snoozed|dismissed], snooze_until NULL)
telegram_outbox(id, notification_id, payload, attempts, next_try_at, sent_at NULL)
settings(key, value)   -- токен хранится зашифрованным
```

## 7. Архитектура

```
TodoDock.App        WPF: HandleWindow, DrawerWindow, NotificationWindow, трей, настройки (MVVM)
TodoDock.Core       Домен: Task/Folder/Reminder, сервисы, планировщик
TodoDock.Data       SQLite, репозитории, миграции
TodoDock.Telegram   Клиент Bot API, очередь отправки
TodoDock.Tests      Юнит-тесты (планировщик, парсер быстрого ввода, очередь Telegram)
```

- MVVM (CommunityToolkit.Mvvm), DI (Microsoft.Extensions.Hosting).
- Один экземпляр приложения (Mutex), повторный запуск → открывает панель.
- Логирование в `%LOCALAPPDATA%\TodoDock\logs`.

## 8. Настройки

Автозапуск · сторона/монитор ручки · раскрытие по клику/наведению · тема (авто/светлая/тёмная) ·
акцентный цвет · звук · «Не беспокоить» · Telegram (токен, чат, тест) · экспорт/импорт JSON.

## 9. Технические риски

| Риск | Решение |
|---|---|
| Окна поверх полноэкранных игр/видео | Не перекрываем fullscreen-приложения (проверка `SHQueryUserNotificationState`), уведомления копятся |
| Кража фокуса при показе | `WS_EX_NOACTIVATE`, `ShowActivated=false` |
| Ручка перекрывает UI других окон у края | Опционально резервировать место как AppBar (`SHAppBarMessage`) — настройка |
| Потеря уведомлений при сбое | Персистентность в SQLite, восстановление при старте |
| Утечка токена | DPAPI, не логировать |

## 10. План реализации

1. **M1 — Каркас**: ручка + выезжающая панель + анимации + трей + автозапуск.
2. **M2 — Задачи и папки**: CRUD, drag & drop, быстрый ввод, SQLite.
3. **M3 — Уведомления**: планировщик, постоянные карточки, snooze, восстановление.
4. **M4 — Telegram**: настройки, привязка, outbox с ретраями.
5. **M5 — Полировка**: темы, Mica, DPI/мониторы, установщик, иконки.

## 11. Принятые решения

1. Ручка только справа (настройка стороны — не в v1).
2. Папки в один уровень (без вложенности).
3. Повторяющиеся задачи — **в v1**: ежедневно / по дням недели / еженедельно / ежемесячно.
   Хранится правило `repeat_rule` (RRULE-подмножество); при выполнении задачи
   создаётся следующее вхождение, напоминание пересчитывается.
4. Telegram только исходящий (без inline-кнопок и входящего polling, кроме разовой привязки чата).
5. Стек .NET 8 + WPF, только Windows 11.

Влияние на план: повторения добавлены в M2/M3 (модель `repeat_rule` в `tasks`,
генерация следующего вхождения в планировщике).
